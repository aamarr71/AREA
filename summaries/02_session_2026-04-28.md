### 3. PII-Redaction für DeepSeek API (Arbeitsauftrag: CC_AUFTRAG_PII_REDACTION.md)

**Motivation:** DeepSeek (China) hat keinen DSGVO-Angemessenheitsbeschluss. Lösung: PII wird vor dem API-Call durch Platzhalter ersetzt, danach wiederhergestellt — DeepSeek sieht nie echte Daten.

**Geänderte Datei:** `server/middleware/deepseek.ts` (einzige geänderte Datei)

**Implementiert:**

`extractPII(data)` → `{ sanitized, piiMap }`
- Erkennt PII-Felder per Key-Name (case-insensitive): Adressen, Makler, Eigentümer, Kontakt, etc.
- Generiert Platzhalter `[PII_N]` und `[PII_N_PARTIAL]` (Straßenname ohne Hausnummer)
- PLZ-only Werte (z.B. "1030") werden nicht redaktiert (kein PII für sich allein)
- Option B: Fließtext-Scanning — ersetzt PII-Werte auch in allen anderen String-Feldern
- Nur für `name`-Keys: prüft zusätzlich ob der Wert wie ein Personenname aussieht

`restorePII(translations, piiMap, originals?)` → `string[]`
- Ersetzt alle Platzhalter im übersetzten Text zurück
- Fallback-Varianten für LLM-typische Klammer-Alterationen: `(PII_1)`, `PII_1`
- Warnt via Pino Logger nur wenn ein Platzhalter im Original vorhanden war aber in der Übersetzung fehlt (kein Rauschen für nicht-relevante Felder)

**System-Prompt erweitert:** PII-Platzhalter-Instruktion steht jetzt an erster Stelle, vor allen anderen Regeln.

**`translateAnalysis()` angepasst:**
```
extractPII(data) → sanitized + piiMap
→ Texte aus sanitized sammeln
→ DeepSeek bekommt sanitized (nie echte PII)
→ restorePII(rawTranslations, piiMap, toTranslate)
→ Return
```

**Tests:** `server/middleware/__tests__/pii.test.ts` — 17/17 grün
- Extraktion + Restaurierung mit realen Daten
- PLZ-only: kein Redact
- Leeres Objekt: kein Crash
- Objekt ohne PII-Felder: kein Crash
- Fallback-Bracket-Varianten: korrekte Restaurierung
